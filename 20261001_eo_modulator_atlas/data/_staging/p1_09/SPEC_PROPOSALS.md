# SPEC proposals from batch p1_09 (li2026ba, lin2025)

Both configs follow the chen2022 conventions; closest valid forms used. Items already raised in the chen2022 pilot (mirror symmetry/mirror_x_um, drive semantics, multi-cell T-rail period, floating bars, variants, bound-type targets, non-CSV target sources) apply here too and are not repeated.

1. Material RF/Pockels data for LiTaO3. `engine/data/materials.json` carries optical dispersion only; `eps_r` and `r_pm_per_v` must be given per config with provenance, and there is no verified reference in the repo. Used: recalled literature values (eps 41/43, r13 8.4) flagged as unverified in provenance; r33 = 30.5 pm/V cross-checked against niels2026 p.9. Propose a verified LT (and LN, BTO) RF/Pockels table with citations next to the optical library, so configs can cite it as `standard_reference` instead of per-config recall.
2. Omitted Pockels keys. `pockelsVoigt` treats absent r22/r51 as 0 silently. Used: only r13 and r33 given and the omission listed in `missing`/`limitations`. Propose a warning (or error) when a crystal material has a partial `r_pm_per_v`.
3. YAML number syntax. `sigma_Sm: 4.9e7` is a string under YAML 1.1 loaders (PyYAML) and a number under YAML 1.2. Verified here with a YAML 1.2 parser. Propose stating YAML 1.2 loader use for schema checks, or writing `4.9e+7`.
4. Conductor edges beside the optical window. The T-bars and Cu electrodes sit 1-2.5 um from the rib, so the optical window had to be cropped inside the conductor edges (zero-field boundary over-confines the mode). Propose allowing conductors in the window with an explicit PEC/Dirichlet treatment for the optical solve, or a separate `optical_domain` larger than the metal-free crop.
5. Waveguide-in-gap placement for two-arm MZMs. Both arms are modelled by hand with the mirror plane away from the origin (see pilot item 1); a `arms: [{x_um, ...}]` helper would remove the repeated polygon bookkeeping.
